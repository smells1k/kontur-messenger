# 💬 Мессенджер «Контур»

[![Сборка .exe](https://github.com/smells1k/kontur-messenger/actions/workflows/build-release.yml/badge.svg)](https://github.com/smells1k/kontur-messenger/actions/workflows/build-release.yml)
[![Скачать](https://img.shields.io/badge/download-KonturServer.exe-6c8cff)](https://github.com/smells1k/kontur-messenger/releases/latest)
[![Android](https://img.shields.io/badge/download-APK%20для%20Android-3ddc84)](https://github.com/smells1k/kontur-messenger/releases/latest)
[![Лицензия: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Мессенджер целиком на **Node.js**: свой сервер (Express + WebSocket), веб-клиент, **готовые `.exe`** для Windows
и **приложение для Android**, которое держит сервер прямо в телефоне.
Текст, файлы, картинки, голосовые, эмодзи (1870 шт.), группы, реакции, ответы, закрепления, поиск,
**видеозвонки и демонстрация экрана (WebRTC)** и **синхронизация между всеми устройствами**.

> **v1.1.0 — «телефон и компьютер».** Клиент переписан: на телефоне один экран вместо трёх колонок
> (чат выезжает поверх списка, свайп и системная кнопка «назад», панели — «шторки» снизу, меню
> сообщения по долгому нажатию, кнопки под палец, учёт «челки» и клавиатуры), на ПК — привычные
> три колонки и горячие клавиши. Приложение ставится как обычное (PWA). Появился **APK для Android**:
> сервер Node.js работает внутри телефона, отдельный компьютер не нужен, друзья подключаются
> по адресу из Wi-Fi. Подробности — в [CHANGELOG.md](CHANGELOG.md).

```
┌──────────────┐   WebSocket + REST    ┌─────────────────────────────┐
│  .exe / веб  │ ⇄  (синхронизация) ⇄  │  KonturServer.exe (Node.js) │
│   клиенты    │   WebRTC (звонки)     │  история + файлы на сервере │
└──────────────┘                       └─────────────────────────────┘
        ▲ друзья в той же сети или по https-ссылке --tunnel
        │
┌───────────────────────────────┐
│ приложение «Контур» на Android│  ← сервер Node.js внутри телефона,
│  (сервер + мессенджер в одном)│    компьютер не нужен
└───────────────────────────────┘
```

## 🚀 Быстрый старт

### Вариант 0 — телефон на Android (сервер в телефоне)

**Скачать: `Kontur-Android-<версия>.apk`** со страницы релизов и открыть файл на телефоне
(Android спросит разрешение на установку из неизвестного источника — это нормально для сборок не из Play).

1. Откройте приложение «Контур» — сервер запустится сам, на экране появится адрес вида
   `http://192.168.x.x:4000`.
2. Нажмите «Поделиться» и отправьте этот адрес другу: он откроет его в браузере или вставит
   в таком же приложении на экране запуска («Подключиться к серверу»).
3. Свой мессенджер откроется тут же, внутри приложения: тот же интерфейс, что и на компьютере.

Телефон и друзья должны быть в одной сети Wi-Fi. Если интернет-адрес нужен всем — держите сервер
на компьютере (`KonturServer.exe --tunnel`) и подключайтесь к нему с телефона.

### Вариант 1 — готовый `.exe` (Windows, ничего ставить не надо)

**Скачать: [KonturServer.exe](https://github.com/smells1k/kontur-messenger/releases/latest)** (собирается автоматически на GitHub Actions)


1. Скопируйте папку `release/` на компьютер с Windows.
2. Двойной клик по **`KonturServer.exe`** → поднимется сервер и **само откроется окно мессенджера**
   (в режиме приложения — без адресной строки браузера).
3. В окне сервера видно адреса:
   ```
   Локально:  http://localhost:4000
   В сети:    http://192.168.1.10:4000   ← этот адрес дайте друзьям в той же сети
   ```
4. На странице входа нажмите **«Регистрация»** — сервер стартует пустым: без чужих чатов,
   демо-людей и ботов. Аккаунт создаётся за 5 секунд.

> Только `.exe` тоже достаточно — веб-клиент распакуется сам в `%LOCALAPPDATA%\Kontur`.
> Данные: `%LOCALAPPDATA%\Kontur\data` (база `db.json` + загруженные файлы).

### Вариант 2 — из исходников (Linux / macOS / Windows с Node.js 18+)

```bash
cd server
npm install
node server.js            # http://localhost:4000, окно откроется не всегда — откройте ссылку сами
node server.js --open     # + автоматически открыть браузер
```
Или просто `./start.sh` (Linux/macOS) / `start.bat` (Windows) из корня проекта.

### Переменные и флаги сервера

| Флаг | Что делает |
|---|---|
| `--port 4100` | другой порт (по умолчанию **4000**) |
| `--host 0.0.0.0` | слушать все интерфейсы (по умолчанию так и есть) |
| `--data DIR` | где хранить `db.json` и загрузки |
| `--no-open` | не открывать окно клиента |
| `--browser` | открыть в обычном браузере (без режима приложения) |
| `--fresh` | **полная зачистка при запуске**: удалить базу, файлы, сертификаты и начать с нуля (запустить один раз, дальше — без флага) |
| `--demo` | **включить демо-стенд**: аккаунты anya/boris/vera/gleb (пароль demo1234), бот `@bot`, готовые чаты. По умолчанию выключен |
| `--https` (или `HTTPS=1`) | включить HTTPS с самоподписанным сертификатом (нужен, чтобы камера/микрофон/экран работали в браузере по IP; сертификат создаётся в `<data>/certs`, в него вписаны все локальные IP — если IP компьютера потом изменился, удалите папку `certs`, он пересоздастся) |
| `--closed` | закрыть регистрацию новых пользователей |
| `--max-upload 100` | лимит загрузки в мегабайтах |
| `--quiet` | меньше вывода в консоль |
| `--tunnel` | (у `.exe`/лаунчера) поднять Cloudflare Tunnel и получить публичную https-ссылку — см. «Как подключить друзей» |
| `--tunnel ТОКЕН` | (у `.exe`) постоянный адрес на своём домене через именной туннель Cloudflare |
| `--server URL` | (у `.exe`) подключиться к чужому серверу вместо запуска своего: `--server http://192.168.1.10:4000` |

## ✨ Что умеет

**Общение**
- Личные чаты и **группы** (до 500 участников), админы, добавление/исключение участников.
- Текст с форматированием: `**жирный**`, `*курсив*`, `~~зачёркнутый~~`, `` `код` ``, ссылки кликабельны.
- **Ответы** на сообщения, **правка**, **удаление**, **закрепления** (до 20), **пересылка**.
- **Реакции** эмодзи (клик по сообщению или долгое нажатие).
- **Галочки доставки/прочтения** (`✓` / `✓✓`), «печатает…», счётчики непрочитанных.
- **Поиск** по чатам и внутри чата с переходом к сообщению.

**Файлы и медиа**
- Перетаскивание файлов в окно, вставка из буфера (Ctrl+V), до 100 МБ.
- Картинки с просмотром на весь экран, видео, аудио, **голосовые сообщения** (запись с микрофона).
- Любые вложения (документы, архивы…) со ссылкой на скачивание.

**Эмодзи**
- **1870 эмодзи** в 9 категориях с поиском по названиям (русские и английские ключи: `сердце`, `heart`, `lol`…).
- Быстрые реакции, недавние эмодзи, эмодзи-аватары профиля и групп.

**Звонки (WebRTC)**
- **Видео и аудио-звонки** в личных чатах и группах (mesh, до 8 человек).
- **Демонстрация экрана** (в браузере — с выбором окна/экрана, в `.exe` — системный выборщик Windows).
- Выключение мик/камеры, индикация «говорит», эффекты картинки (размытый фон, ч/б, сепия, тёплый/холодный/винтаж).
- Входящий звонок: рингтон, всплывающее окно, уведомление ОС; если вошли с другого устройства — предложение присоединиться.

**Синхронизация (главное)**
- Каждое событие (сообщение, правка, реакция, прочтение, изменение группы, звонок) получает номер в **журнале событий**.
- Клиент хранит последний номер `seq` (в браузере и в `.exe` отдельно) и при подключении досылает пропущенное → **включаете ноутбук, а там уже вся переписка**.
- Открыли два окна/устройства под одним логином — всё синхронизируется мгновенно, показывается число устройств в сети.
- **Офлайн-очередь**: сообщение, отправленное без сети, сохраняется и уходит автоматически при подключении (значок «часики»).
- Локальный кэш истории (IndexedDB) — чат открывается мгновенно даже до ответа сервера.

**Прочее**
- Тёмная/светлая тема, уведомления рабочего стола, звуки, адаптивная вёрстка (телефон/планшет/десктоп).
- Показывает «онлайн/был(а) недавно», количество участников онлайн.
- Встроенный бот `@bot` (демо-режим, флаг `--demo`): `/help`, `/time`, `/roll 100`, `/id`, `/stats`, `/echo`, `/ping`, `/me`; в группе отзывается на `@bot`.

## 🔌 Как подключить друзей — три уровня доступа

Сервер всегда слушает всю сеть (`--host 0.0.0.0`), поэтому «локально» он не заперт: вопрос только в том,
докуда достаёт адрес. Вот три уровня — от самого простого к «работает откуда угодно».

### 1. Друзья в той же сети (Wi-Fi/кабель) — ничего настраивать не надо
1. Запустите сервер на одном компьютере — он и есть общий.
2. В консоли сервера напечатан адрес вида `http://192.168.1.10:4000` (строка «В сети»). Его же можно узнать через `ipconfig`.
3. Друзья открывают этот адрес у себя — переписка общая.
4. Если не заходят — разрешите приложение в **брандмауэре Windows для частных сетей**
   (или добавьте правило вручную: `netsh advfirewall firewall add rule name="Kontur" dir=in action=allow protocol=TCP localport=4000`).

> Камера, микрофон и демонстрация экрана при этом **не заработают**: браузеры блокируют их на `http://` вне
> localhost. Для звонков нужен уровень 2 или 3.

### 2. Из интернета без настройки роутера — `--tunnel` (рекомендуется)
Одна команда поднимает Cloudflare Tunnel и печатает публичную **https**-ссылку:

```bash
KonturServer.exe --tunnel            # Windows
node launcher/src/main.js --tunnel   # из исходников (нужен cloudflared)
```

1. Если `cloudflared` не установлен — мессенджер сам подскажет: скачайте один файл
   [cloudflared.exe](https://github.com/cloudflare/cloudflared/releases/latest) и положите рядом с `KonturServer.exe`.
2. В консоли появится ссылка вида `https://quiet-river-9f3k.trycloudflare.com` — её и давайте друзьям.
3. Порт на роутере открывать не нужно, «белый» IP не нужен, друзья могут быть в любой сети.
   Ссылка живёт, пока запущен сервер и туннель.
4. **Плюс бонусом:** это HTTPS, поэтому камера, микрофон и демонстрация экрана работают у всех,
   с телефонов и из любого браузера.

> ⚠️ Кто знает ссылку — может зарегистрироваться. Когда все свои аккаунты созданы, перезапустите
> с флагом `--closed` — регистрация закроется, а вход останется.

### 2.5. Постоянный адрес вместо случайного (свой домен)
Ссылка из быстрого туннеля меняется при перезапуске. Если нужен **один и тот же адрес**
(например `kontur.ваш-домен.ру`), сделайте именной туннель — это бесплатно, нужен только домен:

1. Домен подключаете к Cloudflare (бесплатный тариф, меняются только NS-серверы).
2. Панель Cloudflare → **Zero Trust → Networks → Tunnels** → *Create a tunnel* → тип **Cloudflared**.
3. В туннеле добавьте **Public hostname**: `kontur.ваш-домен.ру` → сервис `HTTP` → `localhost:4000`.
4. Скопируйте **токен** туннеля и запустите сервер:
   ```bash
   KonturServer.exe --tunnel eyJhIjoiXXXX...      # токен из панели (он длинный)
   ```
   Мессенджер сам поднимет `cloudflared tunnel run --token …`, и адрес `https://kontur.ваш-домен.ру`
   будет работать всегда — пока запущен сервер. HTTPS даёт Cloudflare, поэтому камера,
   микрофон и демонстрация экрана работают у всех.

**Альтернативы без своего домена:**
- **DuckDNS** (`ваш-ник.duckdns.org`) — бесплатное имя + клиент-обновлятор; но нужен проброс порта
  на роутере и «белый» IP (за CGNAT не сработает).
- **Tailscale Funnel** — `tailscale funnel 4000` даёт постоянный адрес `https://имя-пк.хвост.ts.net`,
  проброс портов не нужен, но нужен аккаунт Tailscale на сервере.
- **ngrok** — `ngrok http 4000` даёт `https://….ngrok-free.app` (в бесплатном тарифе адрес меняется).

### 2.6. Адрес вместо IP внутри своей сети
Друзьям не обязательно давать `192.168.x.x` — в домашней сети Windows имена компьютеров
и так работают: пусть откроют `http://ИМЯ-КОМПЬЮТЕРА:4000` (имя видно в «Пуск → Этот компьютер»,
например `DESKTOP-7K2L`). Если компьютер умеет mDNS (Windows 10+/macOS/Linux), сработает и
`http://имя-компьютера.local:4000`. Чтобы имя не менялось — задайте компьютеру постоянный IP
в настройках роутера (DHCP reservation), тогда `http://192.168.1.50:4000` будет всегда тем же.

### 3. Свой домен / постоянный сервер (VPS, домашний сервер, NAS)
- `docker compose up -d` на сервере и **обратный прокси** (nginx/Caddy/Traefik) с настоящим сертификатом:
  Caddy в одну строку — `your.domain.com { reverse_proxy localhost:4000 }`, WebSocket проксируется автоматически.
- Или проброс порта на роутере (`4000 → компьютер с сервером`) плюс `--https`, если прокси не хочется.
- Для «своих» без публикации в интернет удобна **VPN-сеть** (WireGuard, Tailscale) — тогда адрес
  будет вида `http://100.x.x.x:4000`, и это уже защищённый канал.

### Если у друга всё равно не спрашивается доступ к микрофону
Пусть он запустит тот же `.exe` как клиент вашего сервера:

```bash
connect-to-server.bat                     # спросит адрес и запустит
KonturServer.exe --server http://192.168.1.10:4000
```

Откроется окно-приложение, в котором разрешения на камеру, микрофон и демонстрацию экрана уже выданы —
даже если сервер открыт по обычному `http`. Краткая инструкция лежит рядом с `.exe` в `README-KLIENT.txt`.

## 🏗️ Сборка `.exe` своими руками

### 1. `KonturServer.exe` — сервер + веб-клиент в одном файле (без установки Node на Windows)

```bash
bash scripts/make-windows-exe.sh
# → release/KonturServer.exe (≈56 МБ) + release/web/
```
Внутрь `.exe` зашиваются Node.js 20, весь сервер и веб-клиент (сборка через
[`@yao-pkg/pkg`](https://github.com/yao-pkg/pkg)). Собирается прямо из Linux/macOS/Windows.

### 2. Полноценное десктопное приложение (Electron + установщик NSIS)

```bash
bash scripts/make-windows-exe.sh        # сначала сервер
bash scripts/build-electron-win.sh      # → release-desktop/Kontur-Setup-1.0.0.exe, Kontur-Portable-1.0.0.exe
```
Скрипт скачает Electron и соберёт:
- **установщик** с ярлыками и пунктом деинсталляции;
- **portable** версию одним файлом;
- клиент сам умеет поднимать локальный сервер (даже без установленного Node) — код сервера лежит в ресурсах приложения.

### 3. Docker (сервер без .exe, лучший вариант для домашнего сервера/NAS)

```bash
docker compose up -d          # http://localhost:4000, данные в ./docker-data
```

```bash
node test/client-smoke.js http://localhost:4100   # клиент «глазами браузера» (jsdom)
node test/e2e.js http://localhost:4100            # полный сценарий: 3 человека, группа, файлы, флуд
node test/client-flows.js http://localhost:4100   # интерфейс «руками»: меню, реакции, ответ, пересылка
node test/call-e2e.js http://localhost:4100       # звонки (настоящий WebRTC)
```
Проверяется: регистрация/вход, WebSocket-авторизация, доставка сообщений, ack, «печатает…»,
ping/pong, реакции (вкл./выкл.), правка, прочтения, вложения и раздача файлов, группы, ответ бота,
поиск, сигналинг звонков, журнал событий и синхронизация, закрытые для чужих чаты.
Клиент в jsdom: вход, список чатов, история, отправка, эмодзи-панель (нет «квадратиков» и составных ZWJ),
вставка и поиск эмодзи, отсутствие дублей сообщений при клике на цитату, панели не перекрывают друг
друга, настройки звука/видео, загрузка своего аватара, очистка локальных данных, темы, чистая консоль,
**офлайн-очередь** (сообщение без сети ждёт и уезжает после возврата связи).
`test/e2e.js` дополнительно проверяет то, что ломается в жизни: у личного чата каждому видно имя
собеседника, служебные сообщения не зажигают счётчик непрочитанных, повторная отправка не создаёт
дубль, вложение со сторонней ссылкой отклоняется, `.html`-файл не превращается в исполняемую страницу,
случайный id в отметке «прочитано» игнорируется, перебор пароля упирается в лимит (а владелец заходит),
слишком большой пакет по WebSocket не принимается.
Тест звонков поднимает **два настоящих WebRTC-пира** через `@roamhq/wrtc` и идёт двумя изолированными
сценариями: сначала сигналинг (приглашение, участие, состояния микрофона и экрана, выход участника),
затем настоящий звонок — соединение доходит до `connected`, медиапоток доезжает до собеседника,
демонстрация экрана подменяет видеодорожку, остановка демонстрации возвращает камеру.
В средах без медиапутей (например, в облачном CI) соединение проверяется мягко: переменная
`CALL_E2E_SOFT_MEDIA=1` превращает эту проверку в «пропущено», сигналинг при этом проверяется строго.

`client-flows.js` проходит по интерфейсу как человек: правый клик по сообщению, быстрые реакции
(и в меню, и кнопкой «😊»), ответ с цитатой, правка, закрепление, пересылка в другой чат, удаление,
панель участников, создание группы, переход из истории к сообщению, поиск по чату, выгрузка `.txt`.

Все пять наборов проходят «в зелёном» и на исходниках, и на **собранной сборке**: CI при каждом пуше
прогоняет их в обычном и демо-режиме, собирает `KonturServer.exe`, и **отдельно проверяет уже
собранный бинарник** — ту же сборку под Linux (это ловит ошибки упаковки, когда файл забыли положить
внутрь `.exe`).

## 🔄 Обновление и зачистка сервера

**Обновиться.** Закройте окно сервера (Ctrl+C в консоли), замените старый `KonturServer.exe`
новым файлом и запустите заново. База при этом не трогается — она лежит отдельно,
в `%LOCALAPPDATA%\Kontur\data`. В окне мессенджера после обновления нажмите `Ctrl+F5`.
Проверить версию: «Настройки» → «Служебное» (или вторая строка в консоли сервера).
Клиент сам раз в сутки спрашивает GitHub о новых релизах и показывает плашку
«Доступна новая версия» со ссылкой на скачивание (`GET /api/server/update`).

**Зачистить сервер (аккаунты, чаты, файлы):**

| Способ | Что делаете | Что получится |
| --- | --- | --- |
| `reset-data.bat` рядом с exe | двойной клик → `y` | удалены база, файлы, настройки |
| флаг `--fresh` | `KonturServer.exe --fresh --no-open` | то же, но в один шаг (запускайте без флага в следующий раз!) |
| вручную | удалить `%LOCALAPPDATA%\Kontur\data` | то же самое |
| только демо | `KonturServer.exe --purge-demo --no-open` | демо-аккаунты и бот удалены, свои переписки целы |

Путь к папке данных виден в консоли (строка «Данные:»), в `GET /health` (поле `data`)
и в настройках клиента.

## ❓ Частые вопросы

**Нужен ли интернет?** Нет — мессенджер работает в локальной сети. Интернет нужен только если сервер и клиенты в разных сетях.

**Где хранится история?** На сервере: `data/db.json` + `data/uploads/`. Копируйте эту папку для бэкапа.

**Как начать с нуля / удалить все данные?** Три способа, от простого к гибкому:
1. **`.exe` на Windows:** рядом с `KonturServer.exe` лежит `reset-data.bat` («Очистить данные») — двойной клик, подтвердить `y`.
   Или запустите сервер один раз как `KonturServer.exe --fresh`.
2. **Из исходников:** `node server/server.js --fresh` (или `node scripts/reset-data.js`, где `--dry-run` покажет план, `--all` дополнительно сбросит ключ сессий).
3. **Руками:** остановить сервер и удалить папку данных — Windows: `%LOCALAPPDATA%\Kontur\data`, исходники: `messenger/data`,
   Docker: `docker compose down -v`.
После зачистки регистрируйтесь заново — база абсолютно пустая.

**Обновил, а в интерфейсе всё по-старому. Что делать?** Проверьте версию: она написана на экране входа
(«версия клиента: …») и в «Настройках» → «Служебное» (там видно и версию сервера, и версию клиента).
Если версии отличаются или старая — это кэш браузера: нажмите `Ctrl+F5` (на Mac `Cmd+Shift+R`).
Начиная с v1.0.3 сервер сам отдаёт клиент с заголовком `no-cache`, поэтому дальше обновления подхватываются
сразу, а при рассинхроне версий внизу экрана появляется плашка «Обновить сейчас».

**Где демо-данные?** По умолчанию их нет — сервер стартует с чистой базой. Нужен наглядный стенд для
показа (аккаунты, группа с историей, бот) — запустите с флагом `--demo`.

**Что если сервер перезапустится?** Ничего не потеряется: база сохраняется атомарно, активные звонки закрываются, клиенты переподключаются сами.

**Как быть с несколькими устройствами под одним логином?** Просто войдите — синхронизация журнальная, история подтянется, а при звонке второе устройство получит уведомление.

**Не работают камера, микрофон или демонстрация экрана?** Если вы открываете мессенджер **в браузере**
по адресу вида `http://192.168.x.x:4000`, браузер запрещает доступ к камере и экрану на «небезопасных»
адресах. Два решения: запустить сервер как `node server.js --https` (сертификат создаётся сам, режим есть
и в `.exe`: `KonturServer.exe --https`), либо открыть клиент в **окне-приложении** (`.exe` запускает его сам)
— там разрешения выданы заранее, и HTTPS не требуется. На `http://localhost` браузеры доступ к камере дают.

**Безопасность?** Пароли — `scrypt` + соль, сессии — самодостаточные JWT (HS256) с секретом в `data/secret.key`. Для публичного интернета поставьте сервер за HTTPS-прокси (nginx/Caddy) — тогда WebSocket станет `wss://`. Встроенный `--https` использует самоподписанный сертификат: браузер один раз попросит подтвердить исключение.

**Размер `.exe` — 43 МБ, это нормально?** Да, внутрь зашиты Node.js и весь клиент, установка не требуется.
